# Workbench Responsiveness, Forms, and Visual Layering Design

## Intent

让 Project Workbench 在输入搜索、切换筛选和 vault 发生变更时保持即时响应；让所有需要输入的字段具备清晰的字段名、用途说明、示例和必要性提示；修复搜索图标与输入文字、最近变化列表图标与文字之间的层叠和溢出问题。

## Goals

- 搜索和本地筛选只使用已加载的内存快照，不因每次按键重新读取全部 Markdown 文件。
- 将短时间内连续的 vault 事件合并为一次刷新，并避免刷新期间重复渲染。
- 所有创建和编辑表单显示可见 label、字段说明、示例或格式提示，并保留现有校验规则。
- 搜索框使用单一、可控的放大镜图标层；最近变化每一行拥有稳定的图标、正文和日期布局，长文本不侵入相邻行。
- 保持桌面端和移动端的现有语义区域、数据格式与操作流程。

## Non-goals

- 不改变 Markdown frontmatter 字段名称、项目快照结构或 vault 写入协议。
- 不引入新的 UI 框架、运行时依赖或后台索引服务。
- 不重做三栏信息架构，也不调整主题配色体系。

## Constraints

- 插件必须继续支持桌面端和移动端。
- vault 读取仍通过 Obsidian API 完成，写入仍使用现有冲突保护逻辑。
- 搜索在默认模式下继续匹配摘要字段，只有启用“搜索正文”时才匹配正文。
- 所有现有测试与构建命令必须保持通过。

## Approaches

1. **局部修复**：只为搜索增加 debounce，给表单增加 label，并调整 CSS。实现快，但搜索仍会重复读取 vault，无法消除主要卡顿来源。
2. **内存快照与合并刷新（选定）**：在视图中缓存文件、项目索引、当前快照和时间线；搜索和筛选从缓存同步渲染；vault 事件通过短 debounce 合并后重新读取一次。表单与视觉问题做局部组件和 CSS 修复。这样能处理卡顿根因，同时保持改动边界清晰。
3. **完整数据层重构**：引入持久化索引和增量文件监听。收益更大，但会增加移动端兼容、失效和数据一致性风险，超出当前问题范围。

## Design

### Cached rendering

`ResearchWorkbenchView` 保存最近一次文件列表、项目索引和时间线所需输入。首次打开和 vault 事件触发异步读取；搜索、问题过滤、字段筛选和正文搜索开关只基于缓存重新生成派生数据并同步渲染。`includeArchived` 改变时从缓存重建项目索引和当前项目快照，不重新读取文件。

vault 的 create/modify/delete 事件进入一个短 debounce 调度器；调度器在同一时间窗口内只安排一次刷新。刷新完成前再次发生的事件只标记下一次刷新，避免并发读取和重复整棵 DOM 渲染。搜索输入采用轻量 debounce，确保连续输入时只触发一次渲染。

### Form clarity

创建和编辑 Modal 使用统一的字段包装结构：可见 label、简短说明、输入控件、示例/格式提示和错误提示。字段值仍使用现有 frontmatter 字段；空值规则保持不变。状态、阶段、研究角色、优先级等枚举或约定字段说明可填写的语义，日期字段明确使用 `YYYY-MM-DD`。

### Visual layering

搜索输入改用普通文本输入并保留 `role="searchbox"`，避免浏览器原生 search 装饰与自定义图标叠加。自定义图标位于独立定位层，输入文字预留稳定左内边距，图标不接收鼠标事件。

最近变化列表行采用固定的最小行高和顶部对齐；图标、正文、日期各自拥有明确的布局约束。正文容器允许收缩，标题和日期对长文本进行省略，行内容不会溢出到相邻行；图标层级保持在本行内部。

## Verification

- 新增缓存渲染和刷新调度测试，证明搜索不会触发文件读取，连续 vault 事件只产生一次刷新。
- 新增表单字段文案契约测试，覆盖问题属性、任务属性、阶段目标和创建表单的 label/说明/示例。
- 新增搜索控件和时间线布局语义测试，覆盖 searchbox 角色、单一图标层和稳定的 timeline item 结构。
- 运行 `npm test`、`npm run typecheck`、`npm run build`。
